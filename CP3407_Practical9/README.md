## Bug Tracking Summary

The project now uses a structured bug reporting process instead of only editing user-story pages. Bugs are recorded with ID, linked user story, severity, priority, reproduction steps, expected result, actual result, assignee, status, and fix evidence.

Recommended GitHub labels:

- `bug`
- `todo`
- `in-progress`
- `done`
- `high-priority`
- `medium-priority`
- `low-priority`
- `system-testing`
- `regression-test`
- `ready-for-review`

## Week 10 Demo Focus

The Week 10 demo should show these complete user flows:

1. Add, edit, delete, and categorize expense records.
2. Set a monthly budget.
3. Trigger budget alerts.
4. Generate monthly financial report data.
5. Analyze spending trends.
6. Test secure login with mock login behaviour.
7. Show GitHub issue tracking and bug status management.
