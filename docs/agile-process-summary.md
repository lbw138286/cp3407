# Agile Software Engineering Summary

The project applied iterative agile development across three iterations.

## Practices used
- User stories to capture requirements from user needs.
- Prioritisation and estimation using person-days.
- Iteration planning based on team capacity.
- Project board with Todo, In Progress, and Done labels.
- Burn-down graphs to monitor remaining work.
- Velocity calculation to adjust future backlog scope.
- Daily/weekly commits and GitHub tracking evidence.
- Testing and bug tracking before the final demo.

## Capacity model
The team has 3 members, with 1 working day per week over 4 weeks. Therefore each iteration capacity is 12 person-days.

The three formal iterations used 36 person-days in total. A separate 6-person-day final-integration allowance covered US1 registration and US2 secure login, giving 42 documented person-days across formal iterations and final integration.

## Iteration velocity
- Iteration 1 actual velocity: 12 person-days.
- Iteration 2 actual velocity: 12 person-days.
- Iteration 3 planned/actual delivery: 12 person-days.

## Final integration

US1 and US2 were completed as cross-cutting identity, authentication and SQLite integration work. Their combined estimate was 6 person-days and was documented separately from the three formal iteration capacities.
