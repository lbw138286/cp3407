# Practical 9 - Teacher Presentation Script

For Practical 9, I focused on bug and error tracking for the Smart Expense Tracker Web Application. The objective was to examine how bugs from system testing should be reported, tracked, fixed, and reviewed.

First, I reviewed the previous tracking method. Before this practical, most progress was documented through user-story pages and project board notes. For this week, I improved the workflow by using GitHub Issues, GitHub Project Board labels, and Pull Requests as the main bug tracking process. This is more suitable because each bug can have its own issue, assignee, priority, severity, reproduction steps, expected result, actual result, comments, and fix evidence.

Second, I created a structured bug reporting process. Each bug report now includes the linked user story, steps to reproduce, expected result, actual result, severity, priority, status, and retest result. I also prepared a GitHub bug report template so future bugs can be reported in the same format.

Third, I created a bug log for the project. The bug log includes several issues found or considered during system testing, such as budget alert threshold checking, monthly report date filtering, spending trend sorting, login validation, and category naming consistency. Some bugs are marked as Done, while one trend-sorting issue remains In Progress and one category consistency issue is still Todo.

Fourth, I updated the relevant user-story GitHub Pages. The updated pages cover US7 Receive Budget Alerts, US8 Generate Monthly Financial Reports, US9 Analyze Spending Trends, and US10 Secure Account Login. Each page includes the user story, completion status, related system tests, related bugs, and current bug status.

Fifth, I prepared a system testing plan for the Week 10 demo. The plan includes 15 system test cases that cover the main user flows: adding expenses, editing and deleting expenses, filtering by category, setting monthly budgets, checking budget alerts, generating monthly reports, analyzing spending trends, testing mock login, and checking local storage persistence.

Finally, I prepared instructions for adding the instructor as a collaborator to the GitHub repository. Since repository access must be changed directly in GitHub settings, I documented the steps to invite Dasheng LIU using the provided email address. During the demo, I can show the repository access page or invitation screenshot as evidence.

Overall, this practical improves the project by adding a clear bug tracking and system testing process. It also prepares the project for the Week 10 demo because the main test cases, known bugs, issue tracking process, and instructor access steps are now documented.
